## 一、严重问题（会导致功能错误）

### S1 `qqGetUrl` 的可插拔降级链实际是死的
循环内无条件 `return`，拿到试听就不再尝试后续 provider。实测注入第二个"能给完整直链"的 provider 后调用会员歌 mid：降级链完全没被使用。与立项 §五「提供方列表 + 逐个降级」相悖，是架构里唯一真正的"可插拔"落点。
→ **已修**：拿到 `complete=false` 时记入 `partial` 并继续试后续提供方；全部试完才把 partial 交上层走回退。

### S2 `isCompleteAudio` 第二重信号会被静默跳过 + 短曲假阳性窗口
1. `if (size > 0 && duration > 0)` —— duration 为 0/undefined 时直接 `return true`，只剩 quality 一道闸。实测 `isCompleteAudio('', 964690, 0) => true`（0.92MB 的 60 秒试听被判完整）。
2. 纯比值法临界：0.92MB 试听在 ≤120.6 秒的完整曲目上算出 ≥64kbps → 假阳性。会员歌只要完整时长 ≤121 秒就会漏过。
→ **已修**：duration 变必需（非正数即判不完整）；并改用上游 `geturl` 返回的实际码率 `kbps` 作主判据（实测试听恒 28kbps、完整 319kbps，与时长无关，短曲也不漏）。

### S3 `qqExtractMid` 漏掉官方/主流分享形式 —— M4 验收必挂
只认 `[?&]mid=` 与 `songDetail/`。实测 `i.y.qq.com/v8/playsong.html?songmid=`、旧版 `/n/yqq/song/*.html` 全部解析失败。关键：vkeys 自己返回的 `link` 字段就是 `i.y.qq.com/...?songmid=` —— 用户复制回来粘贴，插件解析不出来。
→ **已修**：补 `[?&](?:song)?mid=`、`/song/<mid>.html`，并对 y.qq.com 链接做 14 位兜底。

## 二、中等问题
- **M1** `parseInterval` 不支持 `1小时2分` / `1:02:03`（实测 →120 / 0）→ 已修（补小时与冒号格式）
- **M2** `parseSize('10.09M')` → 10 字节、`'1,234,567'` → 1 字节（单字母单位与千分位）→ 会把完整歌误判成试听 → 已修（锚定正则 + 去千分位 + 绝对值）
- **M3** `toHttps` 只匹配小写 → 大写 `HTTP://` 不改写，进 `stripScheme` 后成 `://`（https 页面静音且不报错）→ 已修（大小写不敏感）
- **M4** `quality` 字段双语义：搜索给「平台最高音质」（如臻品全景声），geturl 给「实际文件音质」（如音乐试听）→ 已修（注释澄清；判定只用 geturl 侧）
- **M5** `pay` 不能当会员判据：实测免费可完整播的歌也标 `pay=付费`→ 已修（仅展示）
- **M6** 缺字段项不过滤，`String(s.id)` 产出字面量 `"undefined"` 传进接口（歌词静默为空）→ 已修（`mapQqSong` 过滤 + 兜底）
- **M7** 业务错误走 HTTP 200 且 `jsonGet` 不看 `code` → 错误无法分类（该回退/该重试/该报链接有误）→ 已修（校验 code + `classifyQqError` 四分类）
- **M8** QQ 封面域 `y.qq.com` 无 `Access-Control-Allow-Origin` → canvas 取色必失败 → 卡片颜色恒为网易云红 `ec4141` → **M5 阶段处理**（QQ 源单独兜底色 31c27c）
- **M9** 详情接口白送的 `kbps` 被丢弃 → 已修（保留并升级为主判据）

## 三、M2 接线风险清单（已全部在 M2 实施中处理）
- **R1（最高危）** QQ 歌被静默按网易云点播：`dianbo()` 用 `song.id` 调网易云接口，而 QQ 的 id 是 vkeys 数字 id，落进网易云 song id 值域 → 会放错歌。必须按 `source` 分流。
- **R2** 类型码硬编码 `NETEASE_TYPE`（卡片与事件），`QQ_TYPE` 定义了却没用 → 必须参数化。
- **R3** https 改写必须在 `stripScheme` 之前（provider 内 `toHttps` → 再入事件）。
- **R4** 事件时长 = 0 会让播放器进度错乱 → QQ 侧用 duration/kbps 兜底。
- **R5** 卡片码率写死 320，QQ 实际 128k → 按返回 quality 映射。
- **R6** 「不可播完整版」有两条路径：试听（正常返回 complete:false）与无音质（抛错），回退链两条都要接。
- **R7** QQ 封面无 CORS → 颜色逻辑回归。
- **R8** 输入分流顺序：QQ 链接规则要置于网易云规则之前。
- **R9** 别用 `pay` / 搜索的 `quality` 预筛会员歌。
- **R10** vkeys 单点：降级链修好之前，"多源预留"是空架子（已修 S1）。

## 四、结论
数据层纯逻辑无"必然算错"的硬错误；3 项阻塞（S1/S2/S3）与 7 项边界问题已全部修复并纳入回归测试。
M2 接线必须同步完成 R1（按 source 分流）与 R2（类型码参数化），否则 QQ 歌会静默播成另一首网易云歌并被标成网易云源。
