# 立项：iirose 点歌插件 × QQ 音乐源（v0.6.0）

立项日期：2026-09-24
前置：`docs/可行性报告.md`（可行性验证已通过）· 用户决策已拍板

---

## 一、目标

在现有 iirose 点歌插件（v0.5.0，纯前端单文件，仅网易云）里新增 **QQ 音乐源**：
关键词或 QQ 音乐链接点播 → 能拿到完整直链的 QQ 歌曲直接播（卡片带 QQ 标识）；拿不到完整版（会员歌/无音质）**自动回退网易云同名单曲**。

## 二、范围

**做**
- QQ 音乐：关键词搜索、链接解析、歌词、封面、时长、直链
- 完整性判断（`quality` + `size` 双校验）
- 网易云回退链（QQ 不完整 → 网易云同名 → 明确失败提示）
- 卡片/事件的 `@2` 类型码 + 源标识 UI
- 直链提供方可插拔（先落地 vkeys，接口留好）

**不做**
- 会员歌完整播放（无绿钻，后端方案已出局）
- 会员歌 60 秒试听降级（用户选择：宁可回退也不给试听）
- 后端/服务端任何部署

## 三、技术方案要点

| 环节 | 做法 |
|---|---|
| 搜索 | `api.vkeys.cn/v2/music/tencent?word=&page=1&num=10` |
| 详情 | `?mid=<mid>`（返回 cover / interval / pay / quality） |
| 歌词 | `/v2/music/tencent/lyric?id=<id>` |
| 直链 | `/v2/music/tencent/geturl?mid=&quality=8`（128k 起步，够用） |
| 完整性判断 | **实际实现**：`quality` 含「试听」→ 不完整；否则看 geturl 返回的**实际文件码率** `kbps`（实测试听恒 28kbps、完整 ≥128kbps，与时长无关，短曲也不漏）；拿不到码率时退回 `size÷duration` 比值；两者都拿不到 → 判不完整（不敢确认就不播） |
| 直链修正 | **`http://` → `https://`**（iirose 是 https 页面，否则混合内容被拦）；大小写不敏感 |
| 回退 | QQ 不完整 → 网易云搜同名（优先歌手一致）→ 完整则播，否则提示"两平台都没有可播版本" |
| 点播 | 卡片 `m__4@2>歌名>歌手>封面>颜色>码率`；事件 `&1{... "b":"@2" ...}` |
| 链接识别 | `songDetail/<mid>`、`?songmid=`（i.y.qq.com/v8/playsong.html 官方移动端分享）、`?mid=`、`/n/yqq/song/<mid>.html`、纯 14 位 mid |

### 实施中与立项不同的地方（实测纠正）

1. **完整性判断换判据**：立项原计划「`size` 与官方 `size_128mp3` 比对」，但 vkeys 搜索不返回官方 size。实际改用 geturl 的 `kbps`（实测试听恒 28kbps、完整 319kbps）——比比值法更稳，短曲也不漏判。
2. **链接识别范围扩大**：官方移动端分享（`i.y.qq.com/v8/playsong.html?songmid=`）是最常见形式，立项时漏了；这也正是 vkeys 返回的 `link` 字段格式（用户复制回来粘贴，原实现解析不出）。
3. **`pay` 字段不可用**：实测标「付费」的歌（莫扎特 k448）也能完整播放，不能拿来预筛会员歌。
4. **QQ 封面域无 CORS**：`y.qq.com` 不带 `Access-Control-Allow-Origin`，canvas 取色必然失败 → 兜底色腾讯绿 `31c27c`。
5. **回退可能落到翻唱版**：网易云没有周杰伦版权，回退同名会命中翻唱（实测「晴天(深情版) - Lucky小爱」）→ 补了「优先同歌手」匹配，并在提示里如实报出回退到谁的版本。

### 第二轮独立审查（M2–M5 接线，子 agent）

发现并已修复：

- **S1 回退文案自相矛盾**：把「整曲时长」当「试听时长」写成「只给 269 秒试听片段」（试听恒 60 秒）→ 改为按 `quality` 判定输出「只给 60 秒试听片段（会员曲目）」；判不了完整性时如实说「接口未给码率/时长，无法判定」
- **M1 事件时长可能为 0**：`d:0` 会让播放器进度错乱，而 UI 仍报「已点播」→ 发送前 `Math.max(1, …)`
- **M2 回退链最坏 ~70 秒无反馈** → 加进度文案（「QQ 音乐：获取直链中…」→「QQ 只给 60 秒试听片段，正在回退网易云…」）
- **M3 封面取色无超时**：封面 CDN 连接挂住会永久卡在「点播中…」→ 3 秒超时兜底
- **M4 两源全挂说成「两个源都没搜到」** → 区分「真没这首歌」与「接口不可用」
- **M5 mid 兜底过宽**：纯数字/纯字母的 14 位串会被当成 mid 从而跳过关键词搜索 → 要求字母数字混合；是 QQ 链接但取不到 mid 时明确报错，不静默降级
- **M6 错误分类写了没人读** → `bad_param` 直接报「歌曲信息有误」，不再无谓回退
- **A2 `start.bat` 指向的 `dist/` 是不含 QQ 的老副本**（本地自测会「QQ 消失」）→ 改指 `release/`，并同步 dist 副本
- **A1 文件头仍写 v0.5.0 / 仅网易云** → 更新为 v0.6.0 双源说明

审查确认无恙的：类型码无漏传（只有 @0/@2 两个发送点）、回退链三条出口齐全、UI 按钮状态在成功/失败/回退后都正确复位、网易云零回归。

新增 `tests/protocol.test.js`（协议层 22 项断言）—— 补上旧 `test/media.test.js` 测的是已废弃 `src/media.js` 模块、覆盖不到发布版的空白。
