# QQ 音乐点播可行性报告

项目：iirose 点歌插件（现有版本 v0.5.0，仅网易云）
目标：支持点播 QQ 音乐的会员歌与非会员歌
验证日期：2026-09-24
验证方式：本机实测脚本（9 个探针）+ Chrome 浏览器端到端播放验证

---

## 一、结论先说

**技术上可行，但"会员歌完整播放"这一项卡在硬约束上，必须做取舍。**

1. **搜索 / 歌词 / 封面 / 时长 / 直链 全部打通**，浏览器端实测：搜到周杰伦《晴天》、拿到歌词、直链在 `<audio>` 里 `loadedmetadata` 成功。
2. **非会员歌（免费歌）**：一部分能拿到**完整**直链（实测 10.09MB 的 HQ 完整版，播放时长 264.4s），另一部分服务端报"无音质"。
3. **会员歌（如周杰伦）**：第三方免费服务只给 **60 秒试听**（实测 duration=60.0s，0.92MB）。完整版拿不到。
4. **会员歌完整播放 = 必须自建后端**，纯前端做不到。三条硬约束：
   - QQ 音乐官方接口（`u.y.qq.com/cgi-bin/musicu.fcg`）**没有 CORS 头**，浏览器 fetch 读不到响应；
   - 官方接口**匿名（uin=0）一律不给直链**——连免费歌都是 `purl=NULL`（实测 5 首免费儿歌全 NULL），老接口直接回 `104003`（需播放票据）；
   - 现有免费第三方（vkeys）**不接受传入用户自己的 uin / cookie**（实测 `&uin=`、`&cookie=`、`&userkey=` 参数全被忽略，返回结果不变）。
5. **好消息**：QQ 音乐的类型码 `@2` 早已在 iirose 点播协议里（卡片 `@2`、事件 `@2`），协议层零成本，不需要逆向。

## 二、实测数据

### 2.1 可用的第三方接口：api.vkeys.cn（落月API）

| 用途 | 接口 | 实测结果 |
|---|---|---|
| 搜索 | `GET /v2/music/tencent?word=<词>&page=1&num=10` | 200，~400ms，CORS 允许任意 Origin |
| 单曲详情 | `GET /v2/music/tencent?mid=<mid>` | 200 |
| 歌词 | `GET /v2/music/tencent/lyric?id=<id>` | 200，返回 LRC 文本 |
| 直链 | `GET /v2/music/tencent/geturl?mid=<mid>&quality=<q>` | 200，`data.url` |
| 账号信息 | `GET /v2/music/tencent/info?id=&uin=<QQ号>` | 200，返回该账号歌单（说明服务端按 uin 管理 cookie） |

搜索返回字段（比 GD-Studio 还全，网易云那套的坑这里都没有）：

```json
{"id":97773,"mid":"0039MnYb0qxYhV","vid":"w0026q7f01a","song":"晴天",
 "album":"叶惠美","singer":"周杰伦","cover":"https://y.qq.com/music/photo_new/T002R800x800M000000MkMni19ClKG.jpg",
 "pay":"付费","interval":"4分29秒","quality":"臻品母带2.0","time":"2003-07-31"}
```

- `cover` 是**真实可用**的封面 URL（网易云那边只有假 URL，得绕道详情接口）；
- `interval` 直接给时长（"4分29秒"），不用像网易云那样用 `size×8÷br` 估算；
- `pay` 字段可判断付费/免费。

音质参数 `quality`：`8`=128k，`9`=320k，`10`=flac，`11`=master，`12/13`=atmos，`14`=hires，`16`=flac24bit。

### 2.2 直链实测

| 样本 | 返回 quality | 直链大小 | 播放器结果 |
|---|---|---|---|
| 晴天 周杰伦（付费） | 音乐试听 | 0.92MB | `loadedmetadata duration=60.0s` → **仅试听** |
| 莫扎特钢琴曲k448（免费） | HQ高音质 | 10.09MB | `loadedmetadata duration=264.4s` → **完整** |
| Aurora（免费） | HQ高音质 | 5.39MB | 完整 |
| 4 首免费歌（儿歌/日文曲） | — | — | 服务端报"当前歌曲无音质或付费专辑" |

两个关键工程细节（**开发时必踩**）：
1. **直链默认是 `http://ws.stream.qqmusic.qq.com/...`** —— iirose 是 https 页面，http 会被混合内容拦截。实测**手动把 `http://` 换成 `https://` 后 206 正常**，所以前端必须做这一步替换。
2. 直链**不校验 Referer**（带 `y.qq.com` Referer 与不带，结果都是 206），播放器可直接播——这点和网易云直链一样。

### 2.3 其他第三方接口：今天全线不可用

| 服务 | 实测 |
|---|---|
| GD-Studio `music-api.gdstudio.xyz` | 只开放 `source=netease`，`tencent/qq/qqmusic/kuwo/kugou/migu` 全 400 |
| 星之阁 `api.xingzhige.com/API/QQmusicVIP/` | `code -2000 此接口维护中` |
| 星海音乐源 `yy.zddyr.top` | 403「QQ 音乐仅对认证用户开放」 |
| 星海备 `zrcdy.dpdns.org` | 410 接口已废弃 |
| `api.xcvts.cn`（公开 key） | 「接口已下架或不存在」 |
| 溯音 `oiapi.net` | 403 维护中 |
| 柳云 `api.liuyunidc.cn` | SSL 证书已过期 |
| Meting 各公共实例（`qijieya`/`qjqq`/`mysqil`） | tencent 源返回空 / 522 / 首页 HTML |
| vkeys 旧版 `/music/tencent/song/link` | `code 110001 cookie异常：账号被风控无法获取` |
| IIROSE-MEDIA-WEB（同类 iirose 项目） | 只做了 GD-Studio(网易云)+B站，**没有 QQ 音乐模块** |

**风险提示**：今天能用的只有 vkeys 一家。第三方免费接口的生命周期就是这么短——架构上必须做成「可插拔后端 + 多源 fallback」（参考 lxmusic 音源插件的写法，它们列了 10+ 个后端逐个降级）。

## 三、方案选项

### 方案 A：纯前端（保持现有架构，零部署）
- QQ 音乐 = 搜索 + 歌词 + 封面 + 时长 + 直链
- 免费歌：能拿到的完整播，拿不到的降级提示
- 会员歌：**播放 60 秒试听**，卡片上标注"试听"
- 架构与现在完全一致（jsdelivr 单文件 + 第三方 API + `@2` 类型码）
- 成本：1 个开发迭代；风险：vkeys 挂了就整个 QQ 源不可用（需要 fallback 列表）
- **可以立刻做，不阻塞**

### 方案 B：纯前端 + 自建轻后端（补全会员歌完整播放）
- 后端（Cloudflare Workers / 腾讯云函数）携带**绿钻 cookie** 转发 QQ 官方 `musicu.fcg` 的 vkey 接口
- 前端只调自己的后端，不再依赖 vkeys 的直链
- 前提：**要有绿钻账号**，且 cookie 会过期需要维护（vkeys 自己就是因为"账号被风控"废掉的，同一个绿钻 cookie 被多人高频使用会被风控）
- 国内可直连的托管点需要选（CF Workers 的 `*.workers.dev` 在国内不稳定）
- 成本：后端开发 + 部署 + cookie 维护；风险：账号风控、合规

### 方案 C：先 A 后 B（推荐）
- 第一步用 A 落地 QQ 源（搜索/歌词/免费歌完整/会员歌试听），顺手把「多源 fallback + 可插拔直链提供方」的架子搭好；
- 第二步若确实需要会员歌完整版，再挂上自建后端作为**最高优先级直链源**，前端逻辑不用重写。

### 方案 D：不做（保持仅网易云）

---

## 四、给决策的三个问题

1. 会员歌「只有 60 秒试听」能否接受？（能接受 → 方案 A 直接开工）
2. 是否有绿钻账号、是否愿意为它维护一个后端和 cookie？（有 → 方案 B/C 可行）
3. QQ 源挂掉时的降级：自动回退到网易云同名单曲？还是只报错？

## 五、决策与定案（2026-09-24，用户拍板）

- **不做会员歌**：会员歌（结果里 `quality` 为"音乐试听"，或 size 明显小于官方完整大小时）**不给试听**，直接走回退。
- **只支持能拿到完整直链的歌**；拿不到 → **自动回退到网易云同名单曲**。
- **无绿钻**（且不愿折腾后端）→ 方案 B/C 排除，**后端方案出局**。
- **定案 = 纯前端**：现有架构不变（jsdelivr 单文件 + 第三方 API + `@2` 类型码），新增 QQ 源 + 完整性判断 + 网易云回退。

### 定案方案的两个已知坑（开发时必须处理）

1. **回退未必成功**：周杰伦等歌手在网易云**同样没有版权**，QQ 拿不到完整 + 网易云也没有 → 回退链走到底也失败。UI 必须给出明确提示（例如"该歌曲仅会员可听/两平台均无版权"），不能让用户点了没反应。
2. **完整性判断要可靠**：建议以 `quality` 字段为准（`"音乐试听"` = 不完整），并用返回的 `size` 与 QQ 官方 `file.size_128mp3/size_320mp3` 做二次校验；`geturl` 报"当前歌曲无音质或付费专辑"（`code 500`）时同样判定为拿不到完整版。

### 遗留风险

- 目前可用第三方只剩 **vkeys 一家**，它挂了 QQ 源就整体不可用 → 直链提供方必须做成**可插拔列表 + 逐个降级**（本次先落地 vkeys，接口预留）。
- vkeys 是个人免费服务，随时可能加 key / 限流 / 风控；点播是实时取直链（vkey 有时效），不做缓存即可。
